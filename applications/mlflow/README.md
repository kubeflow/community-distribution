# MLflow

This directory deploys MLflow as Kubeflow's multi-user experiment tracking
service. MLflow workspaces map to Profile namespaces carrying the
`app.kubernetes.io/part-of=kubeflow-profile` label. The Kubernetes authorization
plugin evaluates each request against the caller's Profile role bindings.

## Layout

- `values-kubeflow.yaml` is the reviewed input to the canonical MLflow Helm chart.
- `upstream/base` is generated by `scripts/synchronize-mlflow-manifests.sh` and
  must not be edited directly.
- `overlays/kubeflow` adds Profile-aggregated view, edit, and administrator roles.

The deployment uses the `kubeflow` namespace, the `/mlflow` URL prefix, the
`kubeflow-gateway` Istio gateway, and the identity headers supplied by the
platform OAuth2-Proxy. The MLflow ServiceAccount can discover Profile namespaces
and submit Kubernetes SubjectAccessReviews. Callers receive MLflow permissions
through the standard Kubeflow Profile roles.

## Install

Install the Kubeflow namespace, Profile controller, Istio, and OAuth2-Proxy
before MLflow. Then run:

```bash
kustomize build applications/mlflow/overlays/kubeflow | kubectl apply -f -
kubectl wait --for=condition=Available deployment/mlflow \
  --namespace kubeflow --timeout=300s
```

Open `/mlflow` through the Kubeflow gateway or use the **MLflow Experiments**
entry in the Central Dashboard.

## Storage

The example profile uses a 2 GiB persistent volume with SQLite metadata and
file-based artifacts. This is suitable for a single-replica evaluation
deployment. Before production use, replace both values with shared services:

- set `mlflow.backendStoreUriFrom` to a Secret containing a PostgreSQL or MySQL URI;
- set `mlflow.artifactsDestination` to S3, Google Cloud Storage, Azure Blob
  Storage, or another shared artifact store;
- disable local storage after both stores are remote; and
- configure the corresponding credentials through `envFrom` or workload identity.

Change `applications/mlflow/values-kubeflow.yaml`, then rerun the synchronization
script. Do not patch the generated base by hand.

## Synchronize

The synchronization script checks out an immutable revision of
`kubeflow/mlflow-integration`, renders its canonical chart with the Kubeflow
values, and validates the generated Kustomize base:

```bash
KUBEFLOW_SYNCHRONIZE_NO_COMMIT=true \
  ./scripts/synchronize-mlflow-manifests.sh
./tests/mlflow_manifests_test.py
```

When updating MLflow, change the full `COMMIT` value in the synchronization
script and the image tag in `values-kubeflow.yaml` together, regenerate the
base, and review the rendered resource difference.
